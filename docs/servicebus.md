# Read-only Azure Service Bus integration

Create a message broker with kind **Azure Service Bus**. Under **Integrations → Azure Service Bus**, select that broker and paste the full Azure Resource Manager ID of its namespace. Choose the shared Azure client secret configured in Fuse, or the deployment's managed identity. A saved integration stores the resource ID and authentication mode. It uses the Azure public cloud management endpoint.

**Test connection** reads the first page of queues. **Inspect** lists queues, reads authorization-rule metadata at the namespace and queue scopes, and compares the queues with the selected broker's inventory. A Reader assignment on the namespace allows metadata inspection. An identity with Reader on one queue can inspect that queue directly when it is named in the broker inventory, even when namespace enumeration is denied.

Namespace policies apply across the namespace. Queue policies apply to the named queue. Send, Listen and Manage are configured SAS rights. Fuse performs metadata GETs using Entra authentication. It does not retrieve SAS keys, send or consume messages, or infer an application's effective access from a policy name. Policies may remain configured when SAS authentication is disabled.

Visibility is reported independently for the queue listing, namespace policies and each queue's policies. Azure can return a filtered list with HTTP 200. Fuse reports limited queue visibility when an inventoried queue outside that list denies a direct read. An empty policy list has unknown visibility because Azure may have hidden existing rules. If a later page fails, earlier observations are retained. An inventory queue absent from the visible results stays unknown. Inspections have a 45-second deadline and a 300-request budget, with up to 100 pages or 1,000 entries per listing.

[Azure queue discovery](https://learn.microsoft.com/en-us/rest/api/servicebus/controlplane/queues/list-by-namespace?view=rest-servicebus-controlplane-2024-01-01) and [queue authorization rules](https://learn.microsoft.com/en-us/rest/api/servicebus/controlplane/queues/list-authorization-rules?view=rest-servicebus-controlplane-2024-01-01) describe the underlying resource metadata.

## Saved reviews

Open **Reviews** beside a namespace. A queue-settings review reads the named queue directly. Enter an ISO 8601 duration such as `PT30M`, an expected maximum delivery count, or an upper bound for dead letters. The dead-letter count comes from ARM queue metadata. Fuse never opens the queue or reads a message. A missing property or inaccessible queue yields unknown.

A SAS policy review compares the exact Send, Listen and Manage rights returned at the selected queue or namespace. Optionally require namespace SAS authentication to be enabled or disabled. A queue Reader can inspect queue rights while the namespace authentication setting remains unknown.

For an Entra role review, bind a Fuse identity to its tenant and service-principal object IDs, select a queue, then choose Sender, Receiver or Owner. By default, a direct assignment of that role on the namespace satisfies the expectation for the queue. Choose **Queue only** if an assignment inherited from a parent scope should count as drift. The evidence lists the scopes of the visible unconditional grants of that role to that principal covering the selected queue. The check reads role assignments through Azure Resource Manager. Missing or conditional evidence can leave the result unknown. Group membership, custom roles, access to sibling queues and message delivery are outside this check's scope.

A topic subscription rule review reads one named SQL filter on a namespace that supports topics. A topic fan-out review checks up to twelve named subscription rules against one example string application property. It supports SQL expressions such as `kind = 'order'`, `1=1` and `1=0`. Supply expectations such as `{"all-events/$Default":true,"orders-only/orders-only":true}`. Unsupported and hidden filters remain unknown. Results apply to the named rules; additional subscription rules or actions can produce more deliveries. Topic rules require Standard or Premium. Basic namespaces support queues.

Connection setup accepts an explicit resource ID or a selection from Azure resource discovery. In **Azure integrations**, add a named credential for one namespace to compare different Reader scopes side by side. The shared credential remains available in the connection form.
